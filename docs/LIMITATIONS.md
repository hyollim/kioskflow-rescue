# 한계와 실증 필요성

- 개인이 만든 비공식 NICE인프라 지원용 포트폴리오 컨셉이다. 회사의 납품·공식 협력·계약·매출·실증 성과는 없다.
- 규칙 기반 조작 신호이며 학습한 AI, 얼굴/음성/시선·장애/연령 감지 또는 LLM API가 아니다.
- 실제 결제·주문 전송·직원 알림·POS·서버·DB는 없다. 카드번호·개인정보를 수집하지 않는다.
- NICE가 이미 제공하는 낮은 화면·저시력·음성주문 등의 접근성 하드웨어를 새로 발명한 것이 아니다. 이 웹앱은 접근성 인증·법적 기준 충족을 보장하지 않는다.
- 규칙의 60초 관측·횟수·대기·쿨다운·거절/제한은 가상 설계다. 느리게 읽기/비활동과 실제 어려움을 완전히 구별하지 못한다. 고령자·장애인 등 실제 다양한 이용자 검증이 필요하다.
- 라이브 브라우저 체험, 가속 데모, 합성 비교 데이터는 분리한다. 통제 실험이 아니며 도움 이후 완료율이나 A/B/C 표로 효과를 주장할 수 없다.
- 이탈은 명시 종료만 집계한다. 새로고침 시 진행 주문은 복원하지 않고 기존 미종료 세션은 남는다. 타임아웃 이탈이나 실제 방문자 수를 알지 못한다.
- 데이터는 브라우저별 localStorage, 최대 2,000 이벤트. 장기 누적·멀티탭 병합·원격 동기화·사용자 인증·운영 감사체계 없음. 저장 불가 시 현재 탭 메모리로만 동작한다.
- 불필요개입 대리지표와 사업성 모델의 오개입률은 분모가 달라 직접 연결할 수 없다. 후자는 실제 관찰로 추정해야 한다.
- 손익 입력·구독료·효과·운영비·권고 임계값은 모두 임의의 가상 가정이다. 고정 월 성과, 동일 기기 가동·가격·공헌이익을 전제한다. 세금·계절성·실제 통합 견적·고장·해지·지원 수요 변화·금융비용은 미반영이다.
- PDF와 README의 화면은 실제 시제품 캡처이며 현장 사진이나 실제 배포 매장 이미지가 아니다.
- 모바일/키보드/확대/대비 기초 검증과 배포 여부의 실제 결과는 TEST_REPORT.md 및 DEPLOYMENT.md에 기록한다. 수행 전에는 통과로 표시하지 않는다.
