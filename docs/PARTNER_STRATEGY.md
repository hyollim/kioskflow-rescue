# 파트너·연동 전략

실제 업체 접촉·MOU·납품·계약 없음. 아래는 필요한 협력사 유형과 평가 제안이다. NICE 기존 공식 파트너십을 본 프로젝트 실적으로 전용하지 않는다.

| 유형 | 역할·필요성 | 선정·검토 기준 | 실증 이전 산출물 |
| --- | --- | --- | --- |
| 키오스크 SW/POS·주문플랫폼 | 화면 이벤트·주문상태 연동 | 화면별 안정 이벤트, 옵션/결제 오류 정의, 기존 UX·접근성 유지, 버전 호환 | 이벤트 계약·샌드박스·에러 복구 테스트 |
| 하드웨어/유지보수 운영사 | 장비·화면 크기·입력장치·현장 지원 | 터치·키패드·음성 모드와 충돌 없음, 현장 SLA·원격 롤백 | 기기 매트릭스·설치/점검 체크리스트 |
| 외식 브랜드/매장 운영사 | 고객 문제·도입비·실증 참여 | 동일 UI·실측 데이터·관측 동의·운영 리스크 감수 범위 | 베이스라인·배정 계획·Go/No-Go 합의 |
| UX/접근성 연구 파트너 | 다양한 이용자의 사용성 확인 | 사용자 통제·포커스·대비·인지부하, 적절한 안내/동의 | 관찰 프로토콜·오개입 분류 기준 |
| 보안/개인정보·계약 자문 | 이벤트 최소화·보관·책임 검토 | 개인식별정보 미전송, 목적·보관·권한·삭제·통합 책임 | 데이터 흐름도·계약 책임 경계 |

## 기술 연동 범위
처음에는 화면 단계·성공/실패·도움 상태만 읽는 이벤트 어댑터와 안내 패널로 제한한다. 결제 승인·주문전송을 제어하지 않는다. 이벤트 중복·순서 뒤바뀜·오프라인·장비 재부팅·기존 화면 복귀를 테스트하고 장애 시 안내 기능만 끌 수 있는 fail-safe를 둔다. 현재 정적 앱에는 실제 SDK/POS/직원 호출 연동이 없다.

## 상업·운영 검토
공동판매/리셀 정산, 설치·지원 책임, 현장 출동비, 콘텐츠 변경 권한, 장비 계약 충돌, 유지개발비, 장애 SLA, 실증 중 중단권, 데이터 소유·보관·삭제를 계약 전에 정의한다. 도입 단가·파트너 수수료는 협상 전 가정이므로 확정값으로 제시하지 않는다.

## 접근 순서
고객 문제 인터뷰 → 파트너의 샌드박스/연동 제약 확인 → 범위·비용 견적 → 제한 실증 → 매출·비용과 UX를 함께 검토. 기술이 가능하다는 이유만으로 제휴나 유료 AI 도입을 결정하지 않는다.
