# 설계 의사결정

## 1. 감지 수단
채택: 익명 UI 조작 이벤트를 활용한 설명 가능한 규칙. 대안: 사용자가 누르는 도움 버튼만 제공(B), 항상 자동 도움 표시, 시선/얼굴 분석, LLM 대화형 도우미. B를 비교 기준으로 남기고 나머지는 개인정보·오탐·비용·하드웨어·운영복잡도 대비 추가 가치 미검증으로 제외한다. 규칙을 AI가 학습했다고 설명하지 않는다.

## 2. 개입 설계
한 번의 비활동만으로 어려움을 단정하지 않는다. 일정 관측 창 내 복수 신호를 요구하고 명시적인 도움 요청은 별도로 처리한다. 제안 → 단계 안내 → 직원 호출 시뮬레이션을 사용자가 선택한다. 거절 후 억제, 화면 전환/완료 시 잔여 안내 정리, 전역 자동 도움 끄기를 둔다. 세부 임계값은 구현 후 RULES.md에 고정한다.

## 3. 정적 아키텍처
React + TypeScript + Vite. 화면/상태, 순수 규칙, KPI 계산, 손익 계산을 분리한다. 서버·계정·실결제·외부 API를 사용하지 않는다. 브라우저 저장 실패 시 메모리로 동작하고 안내한다. 화면 이동은 단일 페이지 탭 방식으로 Pages 새로고침 경로 문제를 피한다.

## 4. 데이터와 실험 정직성
실제 체험(브라우저 조작), 데모 시나리오(재현용 합성), 비교용 합성 데이터의 출처를 명시한다. 데이터셋을 섞어 성과로 보이지 않게 한다. 미종료 세션을 이탈로 간주하지 않는다. 도움 이후 완료율은 인과효과가 아니라 관측 비율이다. 거부 후 신속 완료는 불필요 개입의 대리지표일 뿐 직접 정답이 아니다.

## 5. 사업성 모델
고객사 관점 증분 현금흐름을 기본으로 하고 공급사 단위경제는 별도로 문서화한다. 거래 회복 공헌이익·직원 비용 절감에서 구독·유지보수·오개입 비용을 차감한다. 초기비는 월 비용과 중복 차감하지 않는다. 음수 현금흐름은 회수 불가로 표시한다. 모든 기본 수치는 가상 가정이다.

## 6. 배포와 저장소 경계
오직 hyollim/kioskflow-rescue 및 feature/autonomous-build. main 수정·병합 금지. Aside는 직접 git push를 실행하지 않는다. 테스트 통과 → 명시적 파일만 커밋 → clean tree 확인 → 승인된 요청 marker 생성 → 원격 SHA 일치 확인 후 다음 단계. 업로드 대기 동안 파일을 수정하지 않는다. 계정/Keychain/전역 Git/LaunchAgent/네트워크 설정 변경과 유료 서비스는 금지한다.

## 7. 시각·접근성 원칙
세로 기기 우선 주문 카드, 최소 44px 이상 목표 터치 영역, 명확한 진행 단계·가격·오류, 가시적 키보드 포커스, 확대 보기. CSS/SVG 도형을 직접 작성하여 외부 이미지 추적과 유료 생성 모델을 피한다. 인증·하드웨어 동등성은 주장하지 않는다.

## 8. Premium Enterprise Minimal 리디자인
운영 셸은 뉴트럴 배경·화이트 표면과 제한적인 파란 활성색을 사용한다. 데스크톱은 216px 사이드바, 태블릿/모바일은 상단 내비게이션으로 전환한다. 고객 주문은 아이보리·차콜의 독립된 카페 화면이며, A/B/C와 재현 컨트롤은 주문 화면 밖에 둔다. KPI는 핵심 4개 → 지원/개입 → 비교/마찰 → 상세 로그 순으로 구분한다. 사업성은 입력 그룹과 판단/손익·비용 구성을 분리한다. Pretendard Variable을 OFL 라이선스와 함께 자체 제공하며 외부 폰트 요청을 하지 않는다.

본문 최소 14px, 고객 주문 버튼 44px 이상, 고정 내비게이션 아래 포커스 여백, 명시적 라벨·오류·포커스를 일관 적용한다. 모바일 표의 가로 스크롤은 표 영역 안에만 허용하고 키보드 접근과 스크롤 영역 이름을 제공한다. 물리 기기와 스크린리더 인증은 주장하지 않는다. [비교·검증 보고서](REDESIGN_REPORT.md)
