# 실증 계획 | Go / No-Go 이전에 확인할 것

아직 실시하지 않은 제안 계획이다. 기간·매장·임계값은 가상 설계이며 효과를 확정한 결과가 아니다.

## 대상·기간
동일 주문 UI를 쓰는 외식/카페 5매장·10기기·6주를 후보로 한다. 고객/운영사와 실제 합의한 수치가 아니다. 소음·혼잡·이용자 구성·기기 차이를 사전 파악하고, 기존 접근성 기능·기본 오류 안내는 모든 방식에 동일하게 유지한다.

## 단계
1주: 동의/안내·보안·현장 요구사항, 이벤트 정의·직원 호출비용 계측 검토, 실제 결제 시스템과 분리한 리허설.
2주: 무개입 기준선 수집, 완료/이탈 판정과 이벤트 누락 검증.
3~4주: 매장×시간대 블록의 A/B/C 교차·균형 배정. 메뉴/가격/기기상태 통제, 혼잡·직원 개입 기록.
5주: 관찰 표본으로 불필요 개입 여부·거절 이유 확인, 오류/접근성 기초 점검, 비용 실측.
6주: 신뢰구간·군집/시간대 민감도, 고객 손익·공급사 지원부하, 유지/중단 의사결정.

## 주요 비교와 표본
주요 비교는 C vs B의 종료 기준 완료율(자동 제안의 추가 가치)이며 A는 기본선 참고다. 배정 단위와 분석 단위를 분리하고 동일 매장·시간대 군집효과를 고려한다. 필요한 표본은 베이스라인 완료율·최소검출효과·유의수준·검정력·다중비교 정책으로 사전 산정한다. 5매장/6주면 충분하다고 단정하지 않는다. 통계적 불확실성이 크면 유의성/우위를 주장하지 않는다.

## 측정
완료·종료·미종료, 초 단위 시간, 직접 도움/자동 제안/수락·거절/직원 호출, 로그 누락률. 현재 웹앱은 명시 종료만 이탈로 기록하므로 실매장에서는 관찰·세션 타임아웃을 포함한 별도 이탈 정의를 검증해야 한다. 실제 직원 소요시간과 공헌이익은 운영 기록으로 측정한다. 개인정보·얼굴·음성·연령/장애 추정 없이 최소 데이터만 수집한다. 보관기간·접근권한·삭제는 고객사 정책/법률 검토 후 결정한다.

## 가상 Go/No-Go 게이트
- C vs B 완료율 차이 +3%p 이상을 후보 효과로 두되, 신뢰구간·분석 단위·하위 그룹 안전성까지 확인.
- 직원 호출률 비증가, 주문 오류·포기·불편 악화 없음.
- 거절 후 신속 자력 완료 대리지표 ≤20%를 UX 조사 트리거로 사용. 실제 오개입률과 동일시하지 않음.
- 실측 비용을 넣은 보수 시나리오에서 고객 월 순편익>0, 단순 회수≤12개월, 공급사 지원 원가 감당 가능.
- 충족/불확실: 소규모 연장 실증 또는 제한 도입. 실패/안전 악화: C 중단, B나 기본 UX 개선으로 회귀.

## 중단 조건
과도한 개입·주문 오류·개인정보 노출·직원 알림 오동작·실제 결제 영향 발생 시 즉시 해당 기능 중단. 규칙/타이머/연동 변경은 버전 고정·승인·재검증 후 반영한다. 현재 포트폴리오 시뮬레이션은 실제 매장 시스템에 연결하지 않는다.
