# 상황 인지 규칙과 개입 통제

구현: src/domain/rules.ts, src/hooks/useRescue.ts. 규칙 기반이며 AI 학습·사용자 능력 추정이 아니다. 임계값은 실증 전 가상 설정이다.

## 신호·관측 범위
현재 익명 세션의 **동일 화면 단계**, 최근 60초(경계 포함), 미래 시각 제외. back_navigation은 돌아온 목적 화면으로 기록한다. 주문 옵션/수량/상품 수정은 option_changed다. 비활동은 마지막 포인터·키보드·의미 있는 화면 조작 이후 경과시간이며 1초 간격으로 평가한다. 센서나 개인정보는 사용하지 않는다.

## 우선순위(위에서 첫 일치)
1. 필수 입력 오류 2회 이상 + 비활동 20초 이상 → 옵션 어려움 후보
2. 같은 화면 왕복 3회 이상 + 비활동 15초 이상 → 화면 왕복 후보
3. 옵션/주문 수정 3회 이상 + 오류 1회 이상 → 수정 반복 후보
4. 비활동 45초 이상 + 선행 오류/왕복/수정 1회 이상 → 대기와 조작 마찰 후보

단독 대기·정상 옵션 선택·오류 한 번 직후에는 자동 개입하지 않는다. 이 후보는 실제 어려움의 확정 판단이 아니다. 오류와 대기처럼 복수 신호가 필요하다.

## A/B/C
- A: 필수 오류 메시지만. 수동/자동 도움과 직원 호출 버튼 없음.
- B: 사용자가 직접 도움 요청. 단계별 안내와 직원 호출 시뮬레이션. 자동 제안 없음.
- C: B 기능 + 위 복합 신호에 따른 짧은 도움 제안. 수락하면 현재 화면별 단계 안내. 자동 도움 끄기 가능.

## 억제·거절·종료
- 시작·완료 화면, 종료된 세션, 자동 도움 off, 안내가 이미 열린 상태에서는 자동 제안하지 않음.
- 제안 사이 최소 30초, 세션당 최대 2회. 수동 요청에는 자동 제안 횟수 제한을 적용하지 않음.
- 제안 거절은 해당 세션 끝까지 자동 재제안 중지. 직접 도움 요청은 여전히 가능.
- 제안 중 자동 도움을 끄면 거절로 기록하고 해당 세션 자동 개입을 억제.
- 열린 자동 제안에서 직접 도움을 누르면 help_requested와 기존 offerId의 help_accepted를 기록해 미해결 제안으로 남기지 않음.
- 모드 변경·주문 종료·다른 데모 실행은 진행 중 세션을 명시 종료(session_abandoned)하고 초기화. 완료 후 재시작은 완료 세션을 이탈로 중복 기록하지 않음.
- 직원 호출은 화면 안내와 이벤트만 발생하며 실제 직원 알림 없음.

## 재현 시나리오
- 옵션 실패: 옵션 화면 + 오류 2회 + 가상 21초 → C 제안
- 왕복: 메뉴/옵션 왕복 3회 + 가상 16초 → C 제안
- 긴 대기: 옵션 오류 1회 + 가상 46초 → C 제안
- 정상/오탐 억제: 메뉴에서 마찰 신호 없이 가상 46초 → 개입 없음
- 거부 후 완료: 동일 옵션 마찰 후 거절 → 유효 옵션·장바구니·검토·모의 결제·완료
- 수락 후 완료: 동일 마찰 후 수락 → 동일 완료 흐름

A/B에서는 동일 합성 신호를 생성하되 자동 제안/수락/거절을 지어내지 않는다. 시나리오는 source=scenario로 구분되고 UI도 가상 신호/가속 시간을 표시한다. 실제 체험 source=live와 구별하며 가상 완료시간을 실사용 시간으로 해석하지 않는다.

## 알려진 한계
규칙은 사용자 의도를 알 수 없다. 천천히 읽기와 실제 어려움을 완전히 구분하지 못한다. 임계값은 실매장·기기·다양한 사용자 실증으로 조정해야 한다. 브라우저 비활성화/타이머 지연, 여러 탭, 새로고침 시 진행 세션 복원은 별도 운영 과제다. 장비 접근성 인증이나 법적 적합성은 검증하지 않는다.
