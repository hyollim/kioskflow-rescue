# KPI 정의와 데이터 해석

구현: src/domain/analytics.ts. 확인일 2026-10-24. 실제 체험은 브라우저 조작일 뿐 실매장 고객 연구가 아니다.

## 공통 모집단
- 출처를 live(직접 체험), scenario(가상 신호·가속 시계), synthetic(정해진 비교 fixture)로 분리. 기본 화면은 live다. 출처 간 합산 없음.
- 동일 출처·모드 필터에서 session_started가 있는 익명 세션만 대상. 중복 event ID 제거, 세션 내 첫 terminal event까지만 사용.
- 종료 세션 = order_completed 또는 명시적 session_abandoned. 미종료 세션은 완료/이탈 분모 및 평균시간에서 제외하고 별도 표시한다.
- 새로고침/탭 종료를 자동 이탈로 추정하지 않는다. 이전 주문 복원도 안 한다. 실제 이탈률에는 현장 이탈 정의와 계측 보완이 필요하다.
- 분모 0은 0% 대신 ‘—’로 표시. 시간은 밀리초 원본 → 초 환산. scenario/synthetic 시간은 가상 경과라고 표시한다.

## 계산식
| KPI | 분자 | 분모/대상 | 해석상 한계 |
| --- | --- | --- | --- |
| 종료 기준 주문 완료율 | 완료 세션 수 | 완료 + 명시 종료 세션 수 | 미종료 제외. 실제 매장 전체 전환율이 아님 |
| 중도 이탈률 | 명시 종료 세션 수 | 종료 세션 수 | 사용자가 종료/모드·시나리오 변경한 경우 포함, 무응답 이탈 누락 |
| 평균 완료시간 | Σ(완료시각−시작시각)/1000 | 완료 세션 수 | 완료자 선택 편향, 가속 시나리오 시간은 실사용 아님 |
| 도움 요청률 | help_requested 1회 이상인 세션 | 시작 세션 | 수동 요청 기준, 세션 내 중복 제거 |
| 자동 개입 발생률 | help_offered 1회 이상인 세션 | 시작 세션 | 전체 모드 필터면 A/B도 분모 포함. C만 선택해 C 내 발생률 확인 |
| 개입 수락률 | 유효 offerId의 최초 응답이 수락인 제안 수 | 고유 자동 제안 수 | 미응답 포함, 수동 도움만으로는 수락 계산 안 함 |
| 개입 거부율 | 유효 offerId의 최초 응답이 거절인 제안 수 | 고유 자동 제안 수 | 수락·거부 합계가 100% 미만일 수 있음(미응답) |
| 도움 이후 완료율 | 도움 이용 후 완료한 종료 세션 | 도움 이용 후 종료한 세션 | 이용=직접 요청 또는 자동 제안 수락. 인과효과 아님 |
| 불필요 개입 대리지표 | 제안 거절 후 추가 도움 없이 30초 내 완료한 제안 | 거절 뒤 세션이 종료된 고유 제안 | 어려움의 실제 정답 아님. 늦은 자력 완료·사용자 이유·의도 파악 못함 |
| 직원 지원 요청률 | staff_assistance_requested 있는 세션 | 시작 세션 | 호출 체험일 뿐 실직원 출동/소요시간 측정 아님 |

## 대리지표와 사업성 입력을 혼동하지 않기
대시보드 대리지표의 분모는 ‘종료된 거절 제안’이다. 사업성 모델의 오개입률 분모는 ‘전체 거래 시도’다. 둘은 **그대로 대입할 수 없다**. 실제 현장 표본 관찰로 불필요 개입 여부와 거래 시도 대비 빈도를 추정해야 한다.

## 이벤트 최소 스키마
id(중복 방지), sessionId(익명 UUID), mode, source, name, step, at, 선택적으로 origin/offerId/고정 reason 코드만 저장한다. 이름·전화·실제 카드·메뉴 자유입력·연령/장애·센서 데이터는 수집하지 않는다. 실제 결제 입력란 없음.

브라우저 localStorage key=kioskflow.events.v1. 최대 2,000개, 오래된 세션 단위 제거. 단일 세션이 상한을 넘으면 시작 이벤트와 마지막 구간만 보존하므로 일부 신호가 누락될 수 있다. 저장 불가/초과 시 메모리 fallback 안내. 초기화는 이 앱 key와 진행 주문만 초기화하며 다른 사이트 데이터는 건드리지 않는다. 여러 탭 동시 쓰기의 병합은 구현하지 않았다.

## 합성 A/B/C 비교 fixture
각 방식 4세션, 완료 3/명시 종료 1로 구성한 12세션. 모든 완료율은 75%로 의도적으로 동일하다. 소요시간·도움 이벤트는 계산 검증용으로 사전 정의했다. 실제 실험·효과·시장 통계가 아니다. 관측 비교는 배정·난이도 차이를 통제하지 않아 어떤 방식의 우위를 보여주지 않는다.
