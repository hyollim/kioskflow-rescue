# PRD | KioskFlow Rescue

작성·확인: 2026-10-24 (KST). 개인 비공식 포트폴리오 제안이며 NICE인프라의 납품·협력 프로젝트가 아니다.

## 문제와 고객
외식·카페 키오스크에서 옵션 선택, 장바구니 수정, 결제 검토에 막히면 거래를 포기하거나 직원을 호출할 수 있다. 발생 규모와 개선 효과는 아직 현장 검증 전인 가설이다. 구매 의사결정자는 다점포 외식 브랜드 운영·디지털 담당자, 매장 운영사 및 키오스크 솔루션사다. 최종 사용자는 디지털 숙련도가 다양한 주문 고객이다. 연령이나 장애 여부를 추정·분류하지 않는다.

## 가치 제안
기존 접근성 기능을 대체하지 않고, 사용 중 조작 신호를 조합해 통제 가능한 도움을 제공하며 거래 회복과 운영비용을 함께 측정한다. NICE의 낮은 화면·저시력·음성주문 지원은 이미 존재하는 공식 제품 기능이다. 이 웹앱은 그 하드웨어 기능 또는 인증을 재현·획득했다고 주장하지 않는다.

## 핵심 사용자 여정
시작 → 카테고리/메뉴 → 옵션 → 장바구니 → 주문 검토 → 모의 결제 → 완료. 결제정보 입력은 받지 않는다. A 기본형 / B 수동 도움형 / C 상황 인지형을 동일 주문 흐름에서 비교한다. C도 규칙 기반이며 학습 모델·LLM은 사용하지 않는다.

## 기능 범위
- 터치·키보드 사용 가능한 한국어 반응형 정적 웹앱
- 오류·비활동·왕복·수정·직접 요청 신호, 복합 감지, 거절·쿨다운·수동 호출
- 재현 가능한 UI 데모 시나리오와 익명 이벤트. 실제 체험 로그와 합성 시나리오 데이터 분리
- 정의된 분모 기반 운영 KPI와 음수 결과를 숨기지 않는 손익 시뮬레이터
- 사업모델·실증·제휴·한계 문서, 실제 화면 기반 한국어 PDF

## 제외
실결제, 실제 직원 호출, 얼굴/음성/생체 분석, 개인식별정보, 백엔드, 실매장 실험, AI API, 법적 접근성 인증, NICE 공식 협력·도입 성과 주장.

## 수용 기준
1. 주문 전 과정을 실제 클릭으로 완료하고 이전 이동·옵션·수량 변경 가능
2. A는 자동·수동 도움 없음, B는 수동만, C는 복합 신호와 사용자 통제로 도움
3. 데모 시나리오가 화면 상태와 이벤트를 함께 변경하고 합성임을 표시
4. KPI 분모·빈 데이터·미종료 세션 처리·시간 단위가 테스트됨
5. 손익 입력 변경으로 권고가 바뀌고 초기비용/운영비/부정 시나리오 검증
6. 모바일·데스크톱 핵심 경로, 새로고침, 초기화, 빌드·테스트를 실제 실행
7. 배포 확인 전 성공 주장 금지. 권한 부족은 배포만 보류하고 로컬 실행/PDF 제공

## 사업적 성공 기준(향후 실증용, 가상 제안)
관측 A/B/C 완료율 차이만으로 인과효과를 주장하지 않는다. 사전 등록한 매장·시간대 무작위/교차 배정에서 완료율 +3%p, 직원요청률 비증가, 불필요개입 대리지표 20% 이하, 고객사 월 순편익 양수를 Go 후보로 둔다. 표본규모·신뢰구간·운영 안전성이 충분하지 않으면 추가 실증한다. 수치는 시장 실측치가 아닌 의사결정용 가상 기준이다.
